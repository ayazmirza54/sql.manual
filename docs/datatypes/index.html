Data types

Every type, and what it is called in each engine. The notes are where the portability traps live — Oracle's DATE carrying a time, MySQL's utf8 not being UTF-8, SQL Server's UNIQUE allowing one NULL.

Numeric

6

Rarely worth the saving over INTEGER on row-based engines because of alignment padding; genuinely useful in columnar stores where compression is per-column.

The default choice for counts and small keys. A surrogate key on a high-volume table should be BIGINT — exhausting a 2.1-billion INT primary key in production is a genuinely bad day.

3

Padding is significant in comparisons in some engines and stripped in others. Use only for genuinely fixed-width codes (ISO country codes, currency codes); otherwise VARCHAR.

VARCHAR(n)Variable-length string with a maximum length.ANSI

In PostgreSQL, VARCHAR(n) and TEXT have identical performance — the length is a constraint, not a storage decision. In MySQL and SQL Server the declared length affects index key size and temp-table allocation, so it does matter.

TEXT / CLOBUnbounded (or very large) character data.ANSI

PostgreSQL TEXT is a first-class type with no penalty. MySQL TEXT is stored off-page and cannot be fully indexed (only a prefix). SQL Server TEXT is deprecated — use NVARCHAR(MAX).

2

Indexing is 1-based in PostgreSQL, Oracle and Trino; BigQuery makes you choose with OFFSET (0-based) or ORDINAL (1-based). Use for small read-whole lists; use a child table for anything you filter or join on.

Where there is no native type, BINARY(16) halves the storage of CHAR(36) and indexes better — at the cost of readability in ad-hoc queries. Prefer time-ordered UUIDv7/ULID over random v4 for any column that will be a clustered key.

Specialized

6

PostgreSQL enums sort in declaration order and can only have values appended (removal requires a type rebuild). MySQL enums are stored as integers, and reordering the list silently changes the meaning of existing data. A lookup table plus a foreign key is more flexible than either.
