SQL Joins cheat sheet

Every join type, what it keeps, and the mistakes that quietly change the result.

The types

INNER JOINOnly matched rows from both sides
LEFT [OUTER] JOINAll left rows + matched right, else NULL
RIGHT [OUTER] JOINAll right rows + matched left
FULL OUTER JOINAll rows from both sides
CROSS JOINn × m rows, no predicate
SELF JOINTable joined to itself via aliases
LATERAL / CROSS APPLYSubquery can see earlier FROM items

Semi & anti joins

WHERE EXISTS (SELECT 1 FROM b WHERE …)Semi join — one row per left row
WHERE NOT EXISTS (…)Anti join — the NULL-safe "has none"
DISTINCT + JOINSame result, usually slower

The classic mistakes

LEFT JOIN + WHERE on the right table⚠ silently becomes an INNER JOIN
NATURAL JOIN⚠ joins on every same-named column — never use
Missing join condition⚠ accidental Cartesian product
Join on a nullable columnNULLs never match — they are dropped
Fan-out from a one-to-many joinSUM double-counts; aggregate before joining

Syntax sugar

JOIN b USING (customer_id)Column appears once, unqualified
JOIN b ON b.id = a.b_id AND b.activeExtra predicates belong in ON for outer joins
LEFT JOIN LATERAL (…) ON TRUETop-N per group
CROSS APPLY (SELECT TOP 1 …)SQL Server / Oracle equivalent

Algorithms

Nested loopSmall outer set + indexed inner key
Hash joinLarge unsorted sets, equality only
Merge joinBoth inputs already sorted
Range join (a.x < b.y)⚠ cannot hash — expect nested loops
