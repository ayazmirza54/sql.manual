CLI

SHOW DATABASES; USE db; SHOW TABLES;Navigate

SHOW FULL PROCESSLIST;Active queries
SHOW ENGINE INNODB STATUS\GDeadlocks, buffer pool, transactions
\GVertical output for wide rows

Types

INT UNSIGNED / BIGINT UNSIGNEDDoubles the positive range
VARCHAR(n)Length affects index and temp-table size
DATETIME vs TIMESTAMPTIMESTAMP is UTC but limited to 1970–2038
DECIMAL(12,2)Money — never FLOAT
JSONBinary; index via a generated column
utf8mb4Real UTF-8. The old "utf8" is 3-byte and cannot store emoji

InnoDB facts

PK is the clustered indexThe table IS the PK B-tree
Secondary indexes store the PKKeep the PK narrow
Random UUID PK → page splitsUse ordered ids or UUIDv7
Default isolation: REPEATABLE READDifferent from most engines
FK columns are auto-indexedUnlike PostgreSQL

Upsert & writes

INSERT … ON DUPLICATE KEY UPDATEUpsert
INSERT IGNORE⚠ swallows every error, not just duplicates
REPLACE INTO⚠ DELETE + INSERT — loses other columns, fires triggers
UPDATE … ORDER BY … LIMIT nBatched updates
LOAD DATA INFILEBulk load, far faster than INSERT

JSON

data ->> '$.k'Extract as text
JSON_EXTRACT(data, '$.k')Extract as JSON
JSON_TABLE(data, …)Shred into rows
JSON_CONTAINS / JSON_SET / JSON_REMOVETest and modify
ALTER TABLE t ADD c AS (data->>'$.k') STORED, ADD INDEX (c)Index a JSON field

Gotchas

group_concat_max_len = 1024⚠ truncates silently — raise it
ONLY_FULL_GROUP_BY off (legacy)⚠ returns arbitrary values
No CHECK enforcement before 8.0.16Re-validate inherited schemas
No transactional DDLMigrations must be individually idempotent
ERROR 1093Cannot read the target table in a subquery — nest deeper
0 rows affectedMay mean "no change", not "no match"
