Cost control

⚠ You pay for BYTES SCANNEDNot rows returned
SELECT * — neverColumnar: naming columns cuts cost directly
bq query --dry_runSee the bytes before you run it
PARTITION BY DATE(ts) + WHERE on the partition columnPrunes whole partitions
require_partition_filter = TRUERejects unpartitioned scans
LIMIT does NOT reduce cost⚠ the scan already happened
Cached results (24 h) are freeByte-identical query text

Table design

PARTITION BY DATE(event_time)Time partitioning (also integer range)
CLUSTER BY user_id, event_nameUp to 4 columns, order matters
partition_expiration_daysAutomatic retention
No indexesPartitioning + clustering replace them
ARRAY<STRUCT<…>>Nested repeated fields instead of joins

GoogleSQL syntax

`project.dataset.table`Backtick-quoted identifiers
SELECT * EXCEPT (a, b)Exclude columns
SELECT * REPLACE (UPPER(x) AS x)Substitute a column
QUALIFY ROW_NUMBER() OVER (…) = 1Filter on a window function
SAFE_CAST(x AS INT64)NULL instead of an error
SAFE.function(…)NULL instead of an error, any function
FROM t, UNNEST(t.items) AS iFlatten a repeated field

Gotchas

No enforced constraintsDeduplicate in your pipeline
No UPDATE-heavy workloadsDML has quotas; it is not an OLTP store
Streaming buffer rowsNot immediately available to DML
ORDER BY on a huge resultMust fit in one worker — use LIMIT
