SQL commands

Every statement in the language, grouped by sublanguage, with its syntax skeleton and whether it is standard or vendor-specific.

Query

6
SELECTRetrieve rows. The clause evaluation order is FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT.SQL-92
SELECT [DISTINCT] cols FROM t [JOIN …] [WHERE …] [GROUP BY …] [HAVING …] [WINDOW …] [ORDER BY …] [LIMIT n]
WITH / WITH RECURSIVECommon table expressions. Name a subquery for reuse and readability; RECURSIVE enables hierarchy and graph traversal.SQL:1999
WITH [RECURSIVE] name AS (query) [, name2 AS (query)] SELECT …
UNION / INTERSECT / EXCEPTCombine result sets vertically. Oracle spells EXCEPT as MINUS. UNION deduplicates; UNION ALL does not and is faster.SQL-92
query1 UNION [ALL] query2
VALUESA literal table constructor. Usable standalone, in a FROM clause, or as the source of an INSERT or a join.SQL-92
VALUES (1, 'a'), (2, 'b')
TABLEShorthand for SELECT * FROM orders. PostgreSQL, ClickHouse and DuckDB.SQL-92
TABLE orders
EXPLAINShow the execution plan. ANALYZE actually executes the statement and reports real timings and row counts.Vendor
EXPLAIN [ANALYZE] [(BUFFERS, VERBOSE)] statement

DML — data manipulation

7
INSERTAdd rows. Always name the columns — positional inserts break when the schema changes.SQL-92
INSERT INTO t (cols) VALUES (…) | SELECT … [ON CONFLICT …] [RETURNING …]
UPDATEModify existing rows. Join syntax differs sharply between engines: FROM (PostgreSQL), JOIN in the UPDATE clause (MySQL), correlated subquery (Oracle).SQL-92
UPDATE t SET col = expr [FROM other] WHERE …
DELETERemove rows. Fully logged and row-by-row; TRUNCATE is far faster for emptying a whole table.SQL-92
DELETE FROM t [USING other] WHERE …
MERGEConditional insert/update/delete in one statement. Not atomic against concurrent writers without a unique constraint.SQL:2003
MERGE INTO target USING source ON cond WHEN MATCHED THEN UPDATE … WHEN NOT MATCHED THEN INSERT …
TRUNCATEEmpty a table by deallocating storage. Rollbackable in PostgreSQL and SQL Server; NOT in MySQL or Oracle.SQL:2008
TRUNCATE TABLE t [RESTART IDENTITY] [CASCADE]
COPY / LOAD DATABulk load and unload. One to two orders of magnitude faster than row-by-row INSERT.Vendor
COPY t FROM 'file' WITH (FORMAT csv)
CALL / EXECInvoke a stored procedure. SQL Server uses EXEC; Oracle uses an anonymous PL/SQL block.SQL:1999
CALL procedure(args)

DDL — data definition

14
CREATE TABLEDefine a table. The column list is portable; storage, distribution and partition clauses are not.SQL-92
CREATE [TEMP|UNLOGGED] TABLE [IF NOT EXISTS] t (col type [constraints], …)
CREATE TABLE ASMaterialise a query as a new table. Copies column names and types only — never constraints or indexes.SQL:2003
CREATE TABLE t AS SELECT …
ALTER TABLEChange a table definition. Whether a given change is instant or a full rewrite is engine- and version-specific.SQL-92
ALTER TABLE t ADD|DROP|RENAME|ALTER COLUMN … | ADD|DROP CONSTRAINT …
DROPRemove an object. CASCADE also drops dependent views and constraints — check dependencies first.SQL-92
DROP TABLE|VIEW|INDEX|SCHEMA [IF EXISTS] name [CASCADE|RESTRICT]
CREATE INDEXBuild an index. Not in the SQL standard at all, despite being universal.Vendor
CREATE [UNIQUE] INDEX [CONCURRENTLY] name ON t (cols) [INCLUDE (…)] [WHERE …]
CREATE VIEWName a query. Stores no data; acts as a security boundary and a compatibility layer.SQL-92
CREATE [OR REPLACE] VIEW v AS SELECT … [WITH CHECK OPTION]
CREATE MATERIALIZED VIEWStore a query result. Refresh semantics differ radically — from manual snapshots to synchronous maintenance.Vendor
CREATE MATERIALIZED VIEW mv AS SELECT … [WITH DATA]
CREATE SCHEMACreate a namespace. In MySQL, "schema" and "database" are the same thing.SQL-92
CREATE SCHEMA [IF NOT EXISTS] name [AUTHORIZATION user]
CREATE SEQUENCEA number generator. Not transactional — rolled-back transactions leave permanent gaps.SQL:2003
CREATE SEQUENCE s START WITH n INCREMENT BY n [CACHE n] [CYCLE]
CREATE FUNCTION / PROCEDUREDefine server-side code. Functions return a value and can be used in queries; procedures can commit.SQL:1999
CREATE [OR REPLACE] FUNCTION f(args) RETURNS type LANGUAGE lang AS $$ … $$
CREATE TRIGGERRun code automatically on write. SQL Server triggers fire once per statement, not per row.SQL:1999
CREATE TRIGGER trg {BEFORE|AFTER|INSTEAD OF} {INSERT|UPDATE|DELETE} ON t FOR EACH {ROW|STATEMENT} …
CREATE TYPE / DOMAINUser-defined types. A DOMAIN is a reusable named type plus constraints.SQL:1999
CREATE TYPE t AS ENUM ('a','b') | CREATE DOMAIN d AS TEXT CHECK (…)
COMMENT ONStore documentation in the catalog. MySQL uses inline COMMENT clauses; SQL Server uses extended properties.Vendor
COMMENT ON TABLE t IS 'description'
RENAMERename an object. Metadata-only in every engine; dependent views may break.Vendor
ALTER TABLE t RENAME TO t2 | RENAME TABLE t TO t2

DCL — access control

4
GRANTGive privileges. Applies only to objects that exist now — use default privileges for future objects.SQL-92
GRANT privileges ON object TO role [WITH GRANT OPTION]
REVOKERemove privileges. Does not cascade to privileges granted onward unless CASCADE is specified.SQL-92
REVOKE privileges ON object FROM role
CREATE ROLE / USERCreate a principal. In PostgreSQL a user is a role with LOGIN; in Oracle a user is a schema.SQL:1999
CREATE ROLE name [LOGIN] [PASSWORD '…']
CREATE POLICYRow-level security. Restricts which rows a role can read and write.Vendor
CREATE POLICY p ON t USING (predicate) WITH CHECK (predicate)

TCL — transactions

7
BEGIN / START TRANSACTIONStart a transaction. Oracle starts one implicitly at the first DML statement.SQL-92
BEGIN [TRANSACTION ISOLATION LEVEL …]
COMMITMake changes durable and visible to other sessions.SQL-92
COMMIT
ROLLBACKUndo the transaction, or rewind to a savepoint.SQL-92
ROLLBACK [TO SAVEPOINT name]
SAVEPOINTMark a point a partial rollback can return to.SQL-92
SAVEPOINT name | RELEASE SAVEPOINT name
SET TRANSACTIONSet the isolation level. Defaults differ: READ COMMITTED in PostgreSQL, REPEATABLE READ in MySQL.SQL-92
SET TRANSACTION ISOLATION LEVEL {READ UNCOMMITTED|READ COMMITTED|REPEATABLE READ|SERIALIZABLE}
LOCK TABLETake an explicit table lock. Almost always the wrong tool — prefer row locks via SELECT … FOR UPDATE.Vendor
LOCK TABLE t IN {SHARE|EXCLUSIVE} MODE [NOWAIT]
SELECT … FOR UPDATELock the selected rows for the rest of the transaction. SKIP LOCKED makes reliable job queues possible.SQL-92
SELECT … FOR UPDATE [SKIP LOCKED | NOWAIT]

Session & utility

8
SETChange a configuration parameter for the session, transaction or server.Vendor
SET [SESSION|LOCAL] parameter = value
SHOWInspect configuration and metadata. MySQL uses SHOW extensively; PostgreSQL mostly for settings.Vendor
SHOW parameter | SHOW TABLES | SHOW CREATE TABLE t
USESwitch the default database or schema. MySQL, SQL Server, Snowflake, ClickHouse. PostgreSQL uses search_path instead.Vendor
USE database
ANALYZERefresh planner statistics. The first thing to try when a plan is inexplicably bad.Vendor
ANALYZE [table]
VACUUMReclaim dead rows (PostgreSQL) or rebuild the file (SQLite). VACUUM FULL takes an exclusive lock.Vendor
VACUUM [FULL] [ANALYZE] [table]
PRAGMASQLite configuration and introspection. foreign_keys must be set on every connection.Vendor
PRAGMA foreign_keys = ON
PREPARE / EXECUTEServer-side prepared statements. Reuse a plan across executions — and the only real defence against SQL injection.SQL-92
PREPARE stmt AS SELECT … ; EXECUTE stmt(args)
DESCRIBE / \dShow a table structure. Every engine spells it differently.Vendor
DESCRIBE t | \d t | sp_help t
