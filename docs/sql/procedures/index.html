Stored procedures, functions & triggers

Procedural SQL in each engine: PL/pgSQL, T-SQL, PL/SQL, and the trigger models — with guidance on when not to use them.

The standard defines SQL/PSM; almost nobody implements it exactly. Each engine has its own procedural language with its own syntax, error handling and transaction semantics.

::: note Volatility categories matter in PostgreSQL IMMUTABLE (same input → same output, no table access), STABLE (consistent within one statement) and VOLATILE (default; anything goes). Marking a function IMMUTABLE lets it be used in an index expression and constant-folded. Marking it wrongly produces silently stale results. :::

#Triggers

A trigger runs automatically on INSERT, UPDATE or DELETE.

::: danger SQL Server triggers fire once per statement Writing a SQL Server trigger as though it fires per row — SELECT @id = id FROM inserted — silently processes only one row of a multi-row UPDATE. Always write set-based trigger bodies against the inserted/deleted tables. :::

TimingPostgreSQLMySQLSQL ServerOracleSQLite
BEFORE rowYesYesNo (use INSTEAD OF)YesYes
AFTER rowYesYesStatement-level onlyYesYes

Statement-levelYesNoYesYesNo
Multiple per eventYes8.0+YesYesYes

::: warn Triggers are invisible action at a distance They fire on every write path — including bulk loads and migrations — and they do not appear in the query that caused them. A slow trigger makes an INSERT mysteriously slow with nothing in the statement to explain it. Use them for auditing and invariants that must hold no matter which client writes; keep business logic in the application, where it can be tested and traced.

They also do not fire for everything: TRUNCATE skips row triggers, and bulk loaders (COPY with certain options, bcp, LOAD DATA) may bypass them entirely. :::

#Security

SECURITY DEFINER (PostgreSQL, Oracle's AUTHID DEFINER, MySQL's DEFINER) lets a low-privilege caller run privileged code. It is the standard way to expose a controlled operation — and a privilege-escalation vector if the function builds SQL from its arguments without quoting, or leaves search_path unpinned.
