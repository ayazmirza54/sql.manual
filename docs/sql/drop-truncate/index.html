DROP, TRUNCATE & COMMENT

Removing objects and data — DROP vs TRUNCATE vs DELETE, cascade behaviour, and recovering from a mistake.

#DROP

EngineDROP TABLE IF EXISTSMultiple tables in one statementCASCADE
PostgreSQLYesYesYes — drops dependent views and FK constraints
MySQL / MariaDBYesYesParsed and ignored
SQLiteYesNoNo
SQL Server2016+2016+No — drop dependents manually
OracleNo (use PL/SQL)NoCASCADE CONSTRAINTS
Snowflake / BigQueryYesNoSnowflake: yes

::: warn PostgreSQL CASCADE is broader than it looks DROP TABLE orders CASCADE also drops every view, materialized view and foreign key constraint that references it — silently, in one statement. Run the drop inside a transaction and inspect the NOTICE output first, or list dependencies with \d+ orders in psql. :::

#Undo options

EngineRecovery mechanism
OracleRecycle bin: FLASHBACK TABLE orders TO BEFORE DROP; (unless PURGE was used)
SQL ServerNone for DROP — restore from backup, or RESTORE … WITH STOPAT for point-in-time
SnowflakeUNDROP TABLE orders; within the time-travel retention window
PostgreSQL / MySQL / SQLiteNone — restore from backup. A DDL transaction that has not committed can still be rolled back in PostgreSQL
BigQueryCREATE TABLE t AS SELECT * FROM t FOR SYSTEM_TIME AS OF … within 7 days

#TRUNCATE

TRUNCATE empties a table by deallocating its storage rather than deleting rows one by one.

DELETE FROM tTRUNCATE TABLE t
TypeDMLDDL
Speed on a large tableO(rows), writes WAL/redo per rowNear-constant
WHERE clauseYesNo
Fires row triggersYesNo
Transactional / rollbackableYesPostgreSQL, SQL Server, Db2: yes. MySQL, Oracle: no (implicit commit)
Resets identity/auto-incrementNoSQL Server, MySQL, Oracle: yes. PostgreSQL: only with RESTART IDENTITY
Reclaims disk immediatelyNo (needs VACUUM/OPTIMIZE)Yes
Blocked by foreign keysEnforced per rowRefused if any FK references the table (unless CASCADE)
LockRow locksACCESS EXCLUSIVE / table lock

::: danger TRUNCATE cannot be undone in MySQL or Oracle Both perform an implicit COMMIT before and after. BEGIN; TRUNCATE t; ROLLBACK; leaves the table empty. In PostgreSQL and SQL Server the same sequence restores every row. :::
