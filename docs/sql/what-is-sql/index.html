What is SQL?

SQL is a declarative language for defining and querying relational data. What the standard covers, and why every engine still differs.

SQL (Structured Query Language) is a declarative language for defining, manipulating and querying data held in a relational database. You describe what result you want; the database's query planner decides how to produce it — which indexes to use, which join algorithm to run, in what order.

That single property explains most of SQL's character. There is no loop in SELECT, no explicit "open file, scan rows". The same query can execute in 3 milliseconds or 3 minutes depending on statistics, indexes and data volume, without a character of it changing.

#A worked example

Nowhere does that statement say "scan the employees table, hash the departments table, aggregate into a hash map". It states a relationship and a shape. The engine picks the strategy.

#The standard, and what it is worth

SQL is standardised by ISO/IEC 9075. The revisions that matter in practice:

RevisionYearNotable additions
SQL-921992The baseline most people mean by "standard SQL": JOIN syntax, subqueries, CASE, string/date types
SQL:19991999Recursive queries (WITH RECURSIVE), triggers, user-defined types, GROUPING SETS
SQL:20032003Window functions, MERGE, sequence generators, XML
SQL:20082008FETCH FIRST … ROWS ONLY, INSTEAD OF triggers, TRUNCATE
SQL:20112011Temporal tables (system- and application-time periods), extended window frames
SQL:20162016JSON functions, row pattern matching (MATCH_RECOGNIZE), polymorphic table functions
SQL:20232023JSON data type, property graph queries (SQL/PGQ), ANY_VALUE

::: warn Conformance is partial, everywhere No shipping database implements the full standard, and every database ships features the standard never described. Treat "standard SQL" as a portability budget, not a guarantee. This reference marks each construct as ANSI or vendor-specific, and shows the differences rather than averaging them away. :::

#The sublanguages

SQL is usually split into functional groups. The boundaries are conventional, not defined by the standard, but the vocabulary is universal:

GroupStands forStatements
DDLData Definition LanguageCREATE, ALTER, DROP, TRUNCATE, COMMENT
DMLData Manipulation LanguageSELECT, INSERT, UPDATE, DELETE, MERGE
DCLData Control LanguageGRANT, REVOKE
TCLTransaction Control LanguageBEGIN, COMMIT, ROLLBACK, SAVEPOINT

Some texts classify SELECT separately as DQL (Data Query Language). Nothing depends on the label.

#Logical evaluation order

SQL clauses are written in one order and evaluated in another. This is the single most useful thing a beginner can memorise, because it explains three quarters of "why can't I use my alias there?" errors.

::: note Engines that relax this MySQL, MariaDB, SQLite and ClickHouse permit SELECT aliases in GROUP BY and HAVING; MySQL also allows them in HAVING per the standard. BigQuery, Snowflake and Databricks additionally allow aliases in WHERE in many positions. PostgreSQL, SQL Server and Oracle do not — code written against the permissive engines does not port. :::

#Set semantics, not row semantics

A SQL table is a multiset (a bag): unordered, duplicates allowed unless a constraint forbids them. Two consequences trip people up constantly:

  • There is no default order. Without ORDER BY, a result's row order is undefined and may change between runs, after a vacuum, or when the plan changes to a parallel scan.
  • NULL is not a value. It is a marker for "unknown", and it makes comparisons three-valued. See NULL handling.
