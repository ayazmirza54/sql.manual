ALTER

Changing live schemas: which ALTERs are instant, which rewrite the table, and how to migrate without downtime.

ALTER TABLE is where portability and safety diverge most sharply. The same statement can be a metadata-only flick in one engine and a multi-hour full-table rewrite holding an exclusive lock in another.

#The operations

Changing a column type is the least portable statement in common use:

EngineSyntax
PostgreSQL, Db2, CockroachDBALTER TABLE t ALTER COLUMN c TYPE BIGINT USING c::BIGINT
MySQL / MariaDBALTER TABLE t MODIFY c BIGINT NOT NULL (repeat every attribute!)
SQL Server / SynapseALTER TABLE t ALTER COLUMN c BIGINT NOT NULL
OracleALTER TABLE t MODIFY (c NUMBER(19))
SQLiteNot supported — rebuild the table
Snowflake, BigQueryWidening only (INT64→NUMERIC, VARCHAR(10)→VARCHAR(20))

::: danger MySQL MODIFY discards omitted attributes ALTER TABLE t MODIFY c BIGINT on a column that was NOT NULL DEFAULT 0 COMMENT 'x' silently drops the NOT NULL, the default and the comment. You must restate the entire column definition every time. :::

#SQLite: the twelve-step rebuild

SQLite supports only ADD COLUMN, RENAME COLUMN, RENAME TO and DROP COLUMN (3.35+). Everything else means recreating the table.

#The expand–contract migration

The portable pattern for changing a column without downtime, on any engine:

  1. Expand — add the new column (nullable, no default). Instant.
  2. Dual-write — deploy code writing both old and new.
  3. Backfill — copy in batches (WHERE id BETWEEN … ), committing each batch, with a pause between them.
  4. Verify — count mismatches; add the NOT NULL constraint as NOT VALID, then validate.
  5. Switch reads — deploy code reading the new column.
  6. Contract — stop writing the old column, then drop it in a later release.

::: warn Transactional DDL is not universal PostgreSQL, SQLite, SQL Server, Db2 and CockroachDB can roll back DDL inside a transaction — a failed migration leaves nothing behind. MySQL and Oracle commit implicitly before and after each DDL statement, so a multi-statement migration that fails halfway leaves the schema in a partial state. Write MySQL and Oracle migrations to be individually idempotent. :::
