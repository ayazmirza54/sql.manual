Full-text, geospatial & temporal SQL

Three specialised domains: text search with ranking, spatial predicates and indexes, and system-versioned temporal tables.

#Full-text search

LIKE '%term%' cannot rank, stem, or use an index. Every engine ships something better.

websearch_to_tsquery accepts user input directly — quoted phrases, or, and -exclusion — without the syntax errors that to_tsquery raises on raw input.

::: tip When to reach for a dedicated search engine Database full-text search is excellent for "find rows matching these words" over one language and modest volumes. Once you need faceting, typo tolerance, synonyms, multilingual analysers, or per-user relevance tuning, Elasticsearch/OpenSearch/Meilisearch will do it better. The cost is a second system to keep in sync. :::

#Geospatial SQL

The OGC/SQL-MM standard defines ST_-prefixed functions, implemented consistently enough that spatial SQL is unusually portable.

::: warn GEOMETRY vs GEOGRAPHY GEOMETRY computes on a flat plane in the units of its SRID — ST_Distance on SRID 4326 geometry returns degrees, which is not a distance. GEOGRAPHY computes on a spheroid and returns metres. Use GEOGRAPHY for anything involving real-world distance; use projected GEOMETRY for local, high-volume work where speed matters. :::

::: danger ST_DWithin, not ST_Distance < x WHERE ST_Distance(a, b) < 2000 computes an exact distance for every row — a full scan. ST_DWithin(a, b, 2000) uses the spatial index's bounding-box filter first. Same result, orders of magnitude apart. :::

#Temporal SQL

SQL:2011 defines two period types: system-versioned (the database records when each row version was current) and application-time (you record when a fact was true in the real world).

  • ✓SQL ServerSupported2016+
  • ✓MariaDBSupported10.3+
  • ✓Db2Supported
  • ✓OracleSupportedFlashback
  • ✓SnowflakeSupportedtime travel
  • ✓BigQuerySupported7 days
  • ✓DatabricksSupportedDelta
  • ✕PostgreSQLUnsupportedtemporal tables extension
  • ✕MySQLUnsupported
  • ✕SQLiteUnsupported

::: note PostgreSQL has no built-in system versioning Use the temporal_tables extension, or the common manual pattern: a valid_from/valid_to pair plus an audit trigger. PostgreSQL's tstzrange type with a GiST exclusion constraint enforces non-overlapping periods better than most native implementations. :::
