Constraints

NOT NULL, UNIQUE, CHECK, DEFAULT, EXCLUDE and deferrable constraints — with the enforcement gaps in each engine.

Constraints are declarative rules the database enforces on every write, from every client, forever. Application-level validation is advisory; a constraint is the only thing that actually guarantees an invariant holds.

#The catalogue

ConstraintGuaranteesIndex created?
NOT NULLValue is presentNo
UNIQUENo two rows share the valueYes (all major engines)
PRIMARY KEYUNIQUE + NOT NULL, one per tableYes
FOREIGN KEYValue exists in the referenced tableNot automatically (except MySQL)
CHECKA boolean expression holds per rowNo
DEFAULTSupplies a value when the column is omittedNo
EXCLUDENo two rows satisfy a set of operator comparisonsYes (GiST) — PostgreSQL only

#UNIQUE and NULL

UNIQUE permits multiple NULLs in most engines, because two unknowns are not known to be equal. SQL Server is the notable exception.

EngineNULLs allowed in a UNIQUE column
PostgreSQLMany. PG 15+ adds UNIQUE NULLS NOT DISTINCT to opt into single-NULL behaviour
MySQL / MariaDBMany
SQLiteMany
OracleMany (but a composite unique key with all columns NULL is not stored)
SQL ServerExactly one — a second NULL violates the constraint
Db2One by default; EXCLUDING NULL KEYS on an index changes it

#CHECK constraints

A CHECK passes when the expression is TRUE or UNKNOWN. A row with NULL in the checked column therefore passes unless you also declare NOT NULL — a subtle and common source of dirty data.

#Adding constraints to a live table

Validating an existing table takes a lock and a full scan. PostgreSQL and Oracle let you split the two phases.

#Deferrable constraints

A deferred constraint is checked at COMMIT rather than at statement end — necessary for circular references and for bulk swaps of unique values.

  • ✓PostgreSQLSupported
  • ✓OracleSupported
  • ✓Db2Supported
  • ⚠CockroachDBDifferent syntaxunique only
  • ✕MySQLUnsupportedFKs deferred only in a sense
  • ✕SQL ServerUnsupported
  • ⚠SQLiteDifferent syntaxFK only DEFERRABLE
  • ✕BigQueryUnsupported
  • ✕SnowflakeUnsupported
  • ✕RedshiftUnsupported

::: note SQL Server and MySQL have no deferrable constraints In SQL Server, drop and recreate the constraint, or use a temporary sentinel value. In MySQL, SET FOREIGN_KEY_CHECKS = 0 disables FK checking for the session — a blunt instrument that lets you commit inconsistent data, so re-enable it and validate afterwards. :::
